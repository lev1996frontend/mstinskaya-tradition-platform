# Handoff: Мстинская традиция — «Живой архив»

## Что переносить

В пакете два прототипа. **Основной — `Мстинская традиция v3 - путь бойца.dc.html`**:
это v2 плюс сквозная механика прохождения турнира, раздел «Снаряжение» и архивная опись.
`Мстинская традиция v2 - живой архив.dc.html` оставлен как предыдущая версия для сравнения —
переносить его не нужно.

Отличия v3 от v2 (всё описано ниже в соответствующих разделах):

- ПОЕДИНОК стал прохождением турнира за одного бойца: выбор бойца → заявка разряда →
  жребий из двух заявленных → до трёх сшибок → результат. Три круга подряд (круг 1,
  полуфинал, сходка), одно поражение заканчивает путь.
- Лестница из трёх ступеней над сценой поединка.
- Турнирная СЕТКА выводится из одного источника (пары первого круга) и реагирует на ход
  прохождения: место бойца показано как «—», пока круг не пройден.
- Новый раздел Л. 08 «Снаряжение»: крупный план архивного рисунка + опись четырёх разрядов.
- Сквозная архивная опись Л. 01 … Л. 10 в шапках разделов.
- В живописном ряду добавлен главный лист — «Торопецкий кулачный бой», 1845.
- Новые анимации: `letter` (кинетическое имя), `dust` (пыль от выпада).

## Overview

Главная страница сайта Мстинской традиции (Буза, русский кулачный бой, Тверская область).
Задача дизайна — не «красивый лендинг», а ощущение пространства состязания: тёмный
материальный мир, архивная типографика, ритуал жребия, турнир как карта, живопись и
архивная фотография как часть композиции.

Страница объединяет: hero, блок СТЕНКА/КРУГ, интерактивный ПОЕДИНОК (жребий + сшибки),
турнирную СЕТКУ с заявленными разрядами, ПРАВИЛА (мини-квиз), ЛИЧНЫЕ ДЕЛА бойцов,
ХРОНИКУ, ЖИВОПИСНЫЙ РЯД и указатель разделов.

## About the Design Files

Файлы в этом пакете — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий
внешний вид и поведение, а не production-код для копирования. Задача — **воспроизвести
эти экраны в существующей кодовой базе** (Next.js + React + TypeScript, судя по
`tsc --noEmit` / `eslint` / `next build` в требованиях проекта), используя её собственные
паттерны: компоненты, токены, `globals.css`, систему шрифтов.

`support.js` — рантайм среды, в которой сделан прототип. **В production он не нужен**,
включён только чтобы HTML открывался локально.

Разметка прототипа написана на инлайновых стилях. При переносе их следует перевести
в принятый в проекте способ (CSS-модули, Tailwind, styled-components) — значения ниже
даны как точные величины, а не как готовые классы.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы, тайминги и состояния — финальные.
Копия должна повторять их точно. Единственное, что заведомо требует замены —
изображения (см. Assets) и демо-данные (имена бойцов, счёт, вопросы правил).

## Motion language

Семь состояний вместо универсальных fade/slide. Все keyframes — в `<style>` прототипа.

| Имя | Назначение | Значения |
|---|---|---|
| `step` | появление блока | `translateY(18px)` → 0, opacity 0→1, `.45s cubic-bezier(.2,.9,.2,1)` |
| `impulse` | нажатие/hover кнопки | сжатие `.985` → перелёт `-5px/1.012` → возврат, `.5s cubic-bezier(.3,.8,.2,1)` |
| `swing` | 3D-переворот навигации | `rotateX(0→180→180→360deg)`, `.85s` |
| `impact` | удар после сшибки | серия `translate3d` ±9px, `.5s` |
| `cam` | дрожь сцены при броске | ±2px, `.28s steps(2, end) infinite` |
| `flow` | вращение кольца-площадки | `rotate(360deg)`, `90s linear infinite` |
| `drift` / `ken` | медленный зум фото | `scale(1.04→1.14)` + сдвиг, `26–46s ease-in-out infinite alternate` |
| `unmask` | раскрытие изображения | `clip-path: inset(0 100% 0 0)` → `inset(0)`, `.9–1.1s` |
| `draw-x` / `draw-y` | прорисовка линий сетки | `scaleX/Y(0→1)`, `.45–.5s`, задержка по кругам |
| `lunge-a` / `lunge-b` | выпад бойцов | `translateX ±34px` + `rotateY`, `.76s` |
| `flash` | вспышка удара | opacity 0→.8→0, `.6s` |

Контраст обязателен: архив — тихо, жребий — напряжение, турнир — движение, результат —
удар, потом тишина. `@media (prefers-reduced-motion: reduce)` обнуляет все длительности.

### 4. ПОЕДИНОК (`#poedinok`) — прохождение турнира

Главная механика v3. Фон `#100E0C` + радиальный `rgba(142,36,29,.14)`. Отдельный слой вспышки:
радиальный `rgba(176,42,32,.55)`, `opacity: 0`, анимация `flash` только в фазе сшибки.

Шапка: «Л. 04 · Поединок · <ступень>» охрой, линия, справа — название фазы цветом фазы.

**Шапка пути (под заголовком).** Grid `minmax(0,1fr) minmax(0,30rem)`, `gap: 48px`,
`border-bottom: 1px solid #322820`, `padding-bottom: 28px`.
Слева: h2 `2.5rem` (заголовок состояния пути) и абзац; пока боец не выбран — три кнопки
выбора (`background: #1B1611`, рамка `#322820`, hover — рамка `#B02A20` + `impulse`;
внутри имя Alegreya `1.375rem` и клуб Plex Mono `0.5625rem`).
Справа: **лестница** — grid `repeat(3, minmax(0,1fr))`, `gap: 1px` на фоне `#322820`.
Каждая ступень: метка круга, состояние (ОЖИДАЕТ / ИДЁТ / ВПЕРЕДИ / ПРОЙДЕН / ПРОИГРАН)
и полоса `height: 2px` — охра у пройденного, красная у текущего и проигранного,
`#2A2119` у будущего. Фон текущей ступени `#241C15`, остальных `#1B1611`.

Сцена: сетка `minmax(0,1fr) minmax(240px,320px) minmax(0,1fr)`.
Вся сцена получает `impact` с задержкой `.5s` в фазе сшибки и `cam` в фазе броска.

**Боец (слева/справа).** Фото 4:3 в `perspective: 1200px`, `transform: rotateY(±9deg)`,
градиент затемнения от края, бейдж заявленного разряда (иконка + название) на плашке
`rgba(16,14,12,.8)`. Под фото: клуб (Plex Mono `0.625rem`), имя, счёт (Plex Mono `2rem`,
красный у победителя). В фазе сшибки фото делает выпад навстречу (`lunge-a` / `lunge-b`).

**Кинетическое имя (левый боец).** Имя разбивается на буквы; каждая — отдельный span
Alegreya `clamp(1.75rem,3vw,3rem)`, `white-space: pre`, анимация `letter .5s
cubic-bezier(.2,.9,.2,1)` с задержкой `i * 0.045s`. Контейнер — flex с `perspective: 700px`
и `justify-content: flex-end`. Имя пересобирается при смене противника, поэтому буквы
«выходят в круг» на каждой новой ступени.

**Куб жребия (центр).** 300×300, `perspective: 900px`. Две концентрические окружности
(`290px` сплошная `#322820`, `214px` пунктирная `#2A2119`) — площадка. Тень под кубом:
эллипс `168×26`, `filter: blur(11px)`, `opacity` падает до `.35` во время броска.
Сам куб — кнопка 132×132, `transform-style: preserve-3d`, шесть граней
`transform: rotateX/Y(...) translateZ(66px)`, фон `#241C15`, рамка `#4A3A28`,
`box-shadow: inset 0 0 34px rgba(0,0,0,.6)`. Иконки: руки, палка, нож, кистень, круг, стенка.
Вращение — `transition: transform 1.15s cubic-bezier(.16,.86,.24,1)` (делится на скорость
ритуала), к целевому углу добавляются 2 полных оборота по X и 3 по Y.

**Пыль от выпада.** Второй эллипс под кубом: `240×42`, `radial-gradient(closest-side,
rgba(176,122,53,.5), transparent)`, `filter: blur(9px)`, `opacity: 0`; в фазе сшибки —
анимация `dust .9s ease-out` (делится на скорость).

**Фазы прохождения:**

| Фаза | Что происходит |
|---|---|
| `idle` | боец не выбран: «Выберите бойца», куб неактивен |
| `declare` | под кубом — «Заявите свой разряд» и четыре кнопки 40×40; выбор переводит в `ready` |
| `ready` | «Готов к жребию», охра; подсказка «нажмите на плиту» |
| `throw` | куб крутится, сцена дрожит (`cam`), тень уходит; 1150 мс / speed |
| `pause` | 320 мс тишины, фаза «Пауза», цвет `#8B7F6B` |
| `result` | грань выпавшего разряда красная, остальные `#4A3A28`; заголовок = название разряда; запись в журнал |
| `bout` | «Обмен N из 3», кнопка «Сшибка N →» |
| `clash` | выпад бойцов, вспышка, `impact`, пыль; 760 мс / speed |
| `over` | результат круга: «Следующий круг →» при победе не в последнем круге, иначе «Начать путь заново» |

**Guard на жребий обязателен.** `throwLot` должен выходить сразу на фазах
`throw`, `pause`, `declare`, `idle`, `bout`, `clash`, `over` и при отсутствии выбранного
бойца. Без последних трёх клик по кубу после результата стирает выигранный круг и
позволяет переигрывать бой бесконечно — премиса «одно поражение заканчивает путь» рушится.

**Заголовок пути ветвится по трём признакам** — `runFighter`, `runOver` и `phase === 'over'`.
При победе не в последнем круге `runOver === null`, поэтому нужна отдельная ветка
(«Круг 1 взят» / «Ершов пройден со счётом 2:1, осталось кругов: 2»), иначе шапка пути
и блок результата показывают противоречащие друг другу заголовки.

Жребий выбирает **не случайное из четырёх**, а один из двух заявленных разрядов —
вашего бойца и его противника.

**Журнал круга** (правая колонка, `380px`): шапка «ЖУРНАЛ КРУГА», до 4 записей
(время Plex Mono + текст `0.875rem`), внизу — четыре счётчика разрядов с иконками,
выпавший подсвечивается красным.

### 5. СЕТКА (`#setka`) — «Карта состязания»

Grid `repeat(4, minmax(0,1fr))`, `column-gap: 56px`. Колонки: Круг 1 (8 бойцов) →
Полуфинал (4) → Сходка (2) → Победитель (1). Колонка — `height: 560px;
justify-content: space-around`.

**Всё строится из одного источника** — массива пар первого круга (`PAIRS`) плюс
словарь клубов (`CLUBS`) и два фиксированных набора «теневых» победителей
(`GHOST_R1`, `GHOST_R2`) — для половины сетки, где вашего бойца нет, чтобы сетка не «плыла».
Противники пути выводятся оттуда же — лестница и сетка не могут рассогласоваться.
Позиция вашего бойца в колонке показана как `—` / «ожидает», пока круг не пройден.

Ячейка — кнопка `height: 54px`, фон `#1B1611`, рамка `#322820`. Состояния:
ваш боец — фон `#2A1A16`, рамка `#B02A20`; пройденный противник — фон `#241C15`,
рамка `#8E241D`, подпись «пройден» цветом `#8E241D`; выбранный кликом — рамка `#B02A20`.
Внутри: имя (`0.875rem/500`, обрезка эллипсисом) и справа иконка заявленного разряда;
ниже клуб или результат. Hover — `translateX(4px)`.

Соединители рисуются, а не стоят готовыми: горизонталь `width: 56px; right: -56px`
с `draw-x`, вертикаль `right: -28px` высотой 70/140/280px с `draw-y`; задержка растёт
по кругам (`ri * .35s`), у ячеек — `ri * .35 + i * .05`. Цвет линии выбранного пути — красный.

## Interactions & Behavior

- **Логотип**: hover увеличивает счётчик, `rotateY(turns * 180deg)`, обратная грань
  показывает следующее оружие по кругу.
- **Навигация**: hover запускает `swing`; обратная грань обязана лежать внутри
  `preserve-3d` родителя, иначе видны обе стороны. Никаких `filter` / `backdrop-filter`
  на предках — они схлопывают 3D.
- **Жребий**: клик по кубу или кнопке. Игнорируется на всех фазах, кроме `ready`
  (см. guard в разделе ПОЕДИНОК) — иначе выигранный круг можно переиграть.
- **Выбор бойца**: клик по карточке запускает путь, сбрасывает счёт и ставит `picked`
  (так боец сразу подсвечен в сетке).
- **Заявка разряда**: три точки входа — под кубом в фазе `declare`, в шапке сетки
  и в личном деле. Все пишут в `declared` — одно состояние.
- **Сшибка**: до двух чистых касаний, максимум три обмена; победитель пишется в журнал,
  пройденный противник попадает в `beaten` и отмечается в сетке.
- **Сетка**: клик по имени — подсветка пути (повторный клик снимает) + переключатель разряда.
- **Квиз**: до ответа видны две кнопки, после — только разбор; счёт и метки накапливаются.
- **Скорость ритуала** — множитель для всех длительностей жребия и сшибки (0.6–1.6).

## State Management

```
logoTurns: number                       // повороты логотипа
phase: 'idle'|'declare'|'ready'|'throw'|'pause'|'result'|'bout'|'clash'|'over'
rx, ry: number                          // углы куба
lot: number|null                        // выпавший разряд 0..3
lotCount: number                        // всего бросков
tally: [number, number, number, number] // счётчики разрядов
journal: Array<{ time, text }>          // до 4 записей, новые сверху
picked: string|null                     // выбранный в сетке боец
declared: Record<string, 0|1|2|3>       // заявленный разряд каждого бойца
round: number                           // номер обмена
exchanges: number[]                     // победитель каждого обмена (0|1)
scores: [number, number]

// прохождение турнира (v3)
runFighter: string|null                 // за кого играем
runStep: 0|1|2                          // текущая ступень
beaten: string[]                        // пройденные противники
runOver: null|'out'|'champion'          // итог пути

quizIndex, quizPicked, score, marks
```

Переходы: `chooseFighter` → `declare`; `declareMine` → `ready`;
`throwLot` → `throw` → (спин) → `pause` → (320 мс) → `result`; `startBout` → `bout`;
`runRound` → `clash` → (760 мс) → `bout` | `over`;
`nextStep` → `declare` следующей ступени; `restartRun` → `idle` с полным сбросом.

Победа на последней ступени ставит `runOver = 'champion'`, любое поражение — `'out'`.
При победе не в последнем круге `runOver` остаётся `null` — это отдельное состояние
«круг взят, путь продолжается», которое надо обрабатывать как `phase === 'over' && !runOver`.

Данных с сервера прототип не запрашивает — всё демо-данные в коде.
При переносе заменить на реальные: составы кругов, регламент правил, участники.
